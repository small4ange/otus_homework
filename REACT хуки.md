Содержание:
  - useState — хранить данные, которые влияют на экран
  - useRef — хранить данные между рендерами, но без перерисовки
  - useEffect — выполнить побочный код после рендера или при изменении чего-то
---
#  useState

  Это “переменная компонента”, которая умеет обновлять интерфейс.
  Пример:
```
  const [count, setCount] = useState(0);
```
  Здесь:
  - count — текущее значение
  - setCount — функция, которая меняет значение
  Если вызвать:
  setCount(1);
  React заново вызовет компонент, и экран перерисуется.
  То есть useState нужен, когда:
  - значение меняется
  - и из-за этого надо обновить UI
  Пример:
  const [isOpen, setIsOpen] = useState(false);
  Если isOpen влияет на показ блока, это типичный useState.

#  useRef

  Это тоже хранение значения между вызовами компонента, но:
  - при изменении ref.current React не перерисовывает компонент
  - это просто “память” типа кэша

  Пример:
```
const lastIdRef = useRef<number | null>(null);
lastIdRef.current = 123;
```
  Экран не обновится. React просто запомнит 123.

  Когда это полезно:
  - сохранить предыдущее значение
  - хранить флаг “уже делали это”
  - доступ к DOM-элементу
  - хранить таймер, id запроса и т.д.

  В случае:
  const lastProcessedTimeRef = useRef<string | null>(null);
  Это буквально: “запомни, какой processed_time мы уже обработали”.

# useEffect

  Это способ сказать React: “после рендера выполни вот этот код”. Пример:
```
  useEffect(() => {
      console.log('компонент показался');
  }, []);
```

  Этот код выполнится один раз после первого рендера. Если так:
```
useEffect(() => {
      console.log('count изменился');
  }, [count]);
```
  то эффект выполнится:
  - после первого рендера
  - потом каждый раз, когда меняется count

  То есть массив зависимостей [count] означает: “следи за count”.
